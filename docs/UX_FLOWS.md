# Chaos 用户流程

本文档记录当前已经实现的用户流程、系统反馈和失败路径。它描述用户现在能够做什么，不把路线图中的未来能力写成现有功能。

功能新增、修改或删除，或者交互、状态、提示和失败处理发生变化时，应在同一次任务中同步更新本文档。

## 统一术语

- 作品：用户创作的一部长篇小说，是界面中的主要业务对象。
- 项目：作品在本地文件系统和代码中的存储单元；界面优先使用“作品”。
- 作品库：Chaos 管理新作品默认存放位置的目录。
- 书架：应用层首页，用于创建和打开作品。
- 作品空间：打开一部作品后的书内界面。
- 章节：作品正文的基本编辑单元。
- Markdown 镜像：由 SQLite 正文生成的可读文件，不是正文事实来源。

## 启动与书架

1. 应用启动后进入书架。
2. 书架读取当前托管作品库和已知项目记录，显示“全部作品”。
3. 每条作品记录显示作品名称、作者 / 题材和最近修改时间。
4. 没有作品时显示“还没有最近作品”。

失败路径：

- Electron preload 或本地 API 未加载时，显示“本地能力未加载”的明确错误，不执行本地操作。
- 作品库或项目记录读取失败时，在全局错误提示中展示 main process 返回的信息。
- 单个托管目录无法识别为 Chaos 项目时，当前扫描会跳过该目录，不阻止其它作品显示。

## 新建作品

1. 用户在书架选择“新建作品”。
2. 对话框收集作品名称，以及可选的作者名称、作品题材和作品简介。
3. 作品名称为空时留在对话框内，提示“请输入作品名称”并聚焦名称输入框。
4. 提交后进入处理中状态，暂时禁止重复提交和关闭对话框。
5. Chaos 在当前作品库中创建内部项目 ID 目录、SQLite 数据库、章节目录、导出目录和默认章节。
6. 创建成功后关闭对话框，刷新书架记录，并直接进入作品空间的写作工作区。

取消与失败：

- 用户可以在创建开始前通过“取消”、关闭按钮、按 Esc 或点击遮罩关闭对话框。
- 用户取消系统目录选择或其它可取消操作时，保持当前页面和数据不变。
- 创建失败时保留对话框及用户已填写内容，并展示明确错误。
- 创建中断时只清理由 Chaos 本次创建的保留文件，不递归删除用户已有目录或文件。

## 打开作品

用户可以通过两种入口打开作品：

- 在书架中选择已有作品记录。
- 选择“打开本地项目”，通过系统目录选择器打开作品库之外的 Chaos 项目。

打开成功后：

1. 读取 `.moqi/project.sqlite` 和 schema 版本。
2. 恢复作品信息、章节列表、当前章节和已保存正文。
3. 进入作品空间的写作工作区。
4. 当前草稿等于最近保存正文，状态显示为已保存。
5. 刷新书架中的作品记录。

失败路径：

- 用户取消目录选择时留在书架，不显示错误。
- 目录不是 Chaos 项目、数据库缺失或数据损坏时留在书架并显示明确错误。
- 数据库版本高于当前应用支持版本时拒绝打开，不尝试降级或覆盖。

## 写作与保存

当前写作工作区包含章节列表骨架、当前章节标题、字数、编辑器、格式工具和保存状态。

1. 用户编辑正文后，草稿状态变为“未保存”。
2. 用户可以选择保存按钮，或按 `Ctrl+S` / `Command+S` 保存。
3. 保存期间状态显示“保存中”，不重复发起同一章节保存。
4. 保存成功后，SQLite 中的正文、字数、更新时间和版本号更新，并尝试同步 Markdown 镜像。
5. 正文和镜像都成功时显示“正文与 Markdown 镜像已保存”。

保存期间继续编辑：

- 保存请求只提交发起时的草稿快照。
- 保存返回后，如果用户已经产生更新内容，旧响应不能覆盖新草稿。
- 新内容继续保持“未保存”，提示保存期间产生的修改仍未保存。

失败路径：

- SQLite 保存失败时保留当前草稿和未保存状态，并显示错误。
- SQLite 成功但 Markdown 镜像失败时，状态显示“正文已保存”，同时显示镜像警告；不得把它描述为正文保存失败。
- 当前作品缺少路径、章节不存在或没有可保存内容时，不执行保存并显示明确错误。

当前限制：

- 章节新增、删除、重命名、排序和真实章节切换尚未实现。
- 自动保存尚未实现。

## 返回书架与关闭应用

没有未保存修改时：

- 返回书架立即离开作品空间。
- 关闭窗口直接完成关闭。

存在未保存修改时，显示三条路径：

- 保存并继续：先保存当前章节；只有保存结果对应最新草稿时才返回书架或关闭窗口。
- 放弃更改：丢弃当前未保存草稿并继续原操作。
- 取消：关闭确认对话框，留在当前作品空间继续编辑。

如果保存失败、镜像警告以外的正文保存失败，或者保存期间又产生了更新草稿，“保存并继续”不会离开当前界面。

## 导出作品

1. 用户进入导出工作区。
2. 选择 TXT 或 Markdown 格式。
3. 如果当前章节存在未保存修改，按钮显示“保存并导出”，系统先保存最新草稿。
4. 只有保存成功且没有更新草稿时才继续导出。
5. 导出服务从 SQLite 的有序章节快照生成文件，不读取 Markdown 镜像作为正文来源。
6. 文件写入作品的 `exports/` 目录。
7. 成功后显示导出完成、章节数量和文件路径。

失败路径：

- 保存失败或保存期间出现更新草稿时停止导出，避免导出旧正文。
- 导出失败时显示明确错误，不修改 SQLite 正文和当前草稿。
- 当前只支持 TXT 和 Markdown；DOCX / EPUB 尚未实现。

## 作品存放位置

1. 用户从应用层进入设置。
2. 设置页读取当前作品存放位置，并标明是软件私有目录还是自定义目录。
3. “打开目录”在系统文件管理器中显示当前目录。
4. “更改位置”通过系统目录选择器设置以后新作品的存放位置。
5. “恢复默认”将以后新作品的存放位置恢复为软件私有目录。

行为边界：

- 更改或恢复位置只影响以后创建的作品。
- 已有作品不会被自动移动、复制或删除。
- 用户取消目录选择时保持原设置。
- 设置读取、保存或打开目录失败时显示明确错误，不静默切换到其它目录。

## 共同状态规则

- 进行中的创建、打开、保存、导出和设置操作应阻止相同操作被重复触发。
- 错误通过全局错误提示展示，用户可以关闭提示。
- 成功、警告和未保存状态必须区分，不能用成功提示掩盖仍未保存的内容。
- Renderer 不能直接操作文件系统或 SQLite；所有本地行为通过 preload 白名单 API 进入 main process。
- 普通浏览器打开 Renderer 时只能展示本地能力不可用提示，不能假装本地操作已经成功。

## 尚未启用的工作区

- 这些工作区的未来方向见 `PRODUCT.md` 和 `ROADMAP.md`。
- 在真实实现前，不在本文档中预设完整流程；实现时由用户确认交互，再同步补充。
